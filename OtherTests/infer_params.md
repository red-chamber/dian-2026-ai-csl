## 运行参数

| 项目 | 值 |
| --- | --- |
| 入口脚本 | `level4_unet/src/infer.py` |
| 设备 | CPU（torch 2.14.0+cpu，8 线程；本机无独显） |
| 推理方式 | 分块推理，块边长 512，重叠 64 |
| 输入表示 | 灰度单通道，归一化到 [0,1] |
| 尺寸处理 | 补齐到 16 的整数倍推理，跑完裁回原尺寸，输出与输入逐像素对齐 |
| 耗时 | 两张合计约 2 分钟（按输出文件时间戳 13:46、13:48 估算，不含模型加载） |

为什么必须分块：全图直推时第一层 64 通道特征图就是 `64 × 500万像素 × 4B ≈ 1.25 GB`，编码器同时持有数张这个量级的张量，本机 WSL 只有 7.6 GB 内存，第一次尝试就是被 OOM 杀掉的。分块后峰值降到 200 MB 以内。

## 观察与局限

印刷文字、填空横线、题号和段落结构都保住了，没有被连带擦掉，这是这个任务最关键的一条。

手写内容大部分被清除，但笔迹密集处留有浅灰残影，例如第一张 NH4Cl 附近、第二张第 31、35、37 题附近。这不是推理配置的问题，是权重本身的水平：训练曲线里验证 PSNR 从第 20 轮起就一直在 21.7~22.0 dB 之间震荡，到第 60 轮都没再提升，而训练损失还在下降，说明模型欠拟合、数据量是主要瓶颈。

输入是 RGB 截图（PixPin 截屏），脚本按 `load_gray` 转成灰度处理，输出是单通道 8 位 PNG。JPEG 有损压缩会在刚擦干净的区域再压出伪影，所以这里存 PNG。
